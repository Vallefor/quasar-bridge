# Quasar Bridge

Quasar Bridge позволяет обращаться к своей нейросети и управлять устройствами
Home Assistant через Яндекс Станцию. Вы по-прежнему говорите «Алиса», а программа
выбирает, кому передать запрос: Яндексу, нейросети или Home Assistant.

Музыка, погода, таймеры и будильники остаются у Яндекса. Для сложных вопросов
можно использовать выбранную вами нейросеть, а для умного дома — устройства,
которые уже настроены в Home Assistant.

**Интернет всё равно нужен:** Яндекс распознаёт речь и озвучивает ответы,
в том числе ответы вашей нейросети. Полностью автономной колонка не становится.

## Что можно делать

| Пример запроса | Что произойдёт |
| --- | --- |
| «Алиса, включи музыку» | Запрос обработает Яндекс |
| «Алиса, какая завтра погода?» | Ответит Яндекс |
| «Алиса, спроси нейросеть: почему небо голубое?» | Ответит подключённая вами нейросеть |
| «Алиса, сравни варианты утепления балкона» | Запрос уйдёт к нейросети |
| «Алиса, выключи свет в кабинете» | Команда уйдёт в Home Assistant, если он подключён |
| «Алиса, горит ли свет в кабинете?» | Программа запросит состояние устройств в Home Assistant |

Так работают стандартные правила. Их можно изменить под свои привычки.
Если Алиса отвечает «не знаю» или похожим отказом, программа в некоторых случаях
передаёт вопрос нейросети. Это возможно, пока колонка ещё не начала озвучивать
ответ и Яндекс не приступил к выполнению команды.

Нейросеть помнит недавние реплики, поэтому ей можно задавать уточняющие вопросы.
Дополнительно можно включить чтение веб-страниц, поиск по истории разговоров
и подключение других сервисов через MCP — протокол, который даёт нейросети
доступ к их инструментам.

## Что понадобится

- **Яндекс Станция с правами администратора (root) и доступом по SSH.**
  Права root нужно получить до установки Quasar Bridge.
- **Доступ к нейросети через API, совместимый с OpenAI.** Нужны адрес API,
  название модели и ключ доступа, если его требует сервис. Нейросеть может
  работать на вашем сервере или у внешнего провайдера. Саму модель Quasar Bridge
  не устанавливает и не запускает.
- **Компьютер для установки и настройки.** Понадобится терминал и возможность
  подключиться к колонке по SSH.
- **Home Assistant, если хотите управлять его устройствами.** Для работы
  только с нейросетью он не нужен.

Программу можно запустить двумя способами:

| Где работает Quasar Bridge | Как установить |
| --- | --- |
| На самой колонке с Linux ARM64 или ARMv7 | Архивом и скриптом установки, без менеджеров пакетов; этот способ описан ниже |
| На отдельном компьютере или Linux-сервере | Собрать из исходников и настроить подключение колонки по [подробной инструкции](docs/guide.md#1-получить-и-собрать-проект) |

Ранее работа программы проверялась на **Станции 2 с ARM64 и Linux 4.9**.
Новые скрипты проверяются автоматически в Linux с BusyBox; установка и
перезагрузка на реальных колонках требуют отдельной проверки.
Для ARMv7 доступна отдельная сборка, но работа на конкретной модели не гарантирована.

## Установка на колонку без менеджеров пакетов

Нужны root, SSH и прошивка с BusyBox и автозапуском `/etc/init.d/S*`.
На колонке достаточно штатных `sh`, `tar`, `gzip`, `wget`, `nohup`, `readlink`
и остальных базовых утилит BusyBox. YAM, Go и Python устанавливать не нужно.
На прошивке с другим механизмом загрузки потребуется свой init hook.

### 1. Выберите сборку

**На компьютере** узнайте архитектуру колонки, заменив `SPEAKER_IP` её адресом:

```sh
ssh root@SPEAKER_IP 'uname -m'
```

| Ответ | Архив |
| --- | --- |
| `aarch64` или `arm64` | `quasar-bridge-VERSION-linux-arm64.tar.gz` |
| `armv7l` или `armv8l` | `quasar-bridge-VERSION-linux-armv7.tar.gz` |

На [странице выпусков](https://github.com/skrashevich/quasar-bridge/releases/latest)
скачайте архив и одноимённый файл `.tar.gz.sha256` **из одного выпуска**.
Старые `.yap` предназначены только для прежнего YAM.
Если в последнем выпуске ещё нет `.tar.gz`, используйте
[сборку из исходников](docs/guide.md#сборка-архива-для-колонки).
Далее замените `VERSION` номером скачанного выпуска, а `arm64` — на `armv7`,
если требуется.

### 2. Установите архив

Если Quasar Bridge уже установлен через YAM, сначала выполните
[переход со старой установки](docs/guide.md#переход-с-yam).

**На компьютере**, в папке со скачанными файлами:

```sh
shasum -a 256 -c quasar-bridge-VERSION-linux-arm64.tar.gz.sha256
scp quasar-bridge-VERSION-linux-arm64.tar.gz root@SPEAKER_IP:/data/
ssh root@SPEAKER_IP
```

На Linux вместо `shasum -a 256 -c` можно использовать `sha256sum -c`.
Продолжайте только после `OK`. При нестандартном порте SSH используйте
`ssh -p PORT` и `scp -P PORT`; при необходимости старого протокола SCP — `scp -O`.

**На колонке**, в открывшемся SSH-сеансе:

```sh
stage=$(mktemp -d /data/quasar-bridge-install.XXXXXX)
tar -xzf /data/quasar-bridge-VERSION-linux-arm64.tar.gz -C "$stage"
sh "$stage/install.sh"
```

Установщик проверит архитектуру и настройки, запустит программу и создаст
автозапуск `/etc/init.d/S98quasar-bridge`. Файлы программы находятся в
`/data/opt/quasar-bridge/app`, настройки — в `/data/opt/quasar-bridge`.
При ошибке запуска обновления установщик возвращает предыдущую версию.
Корневая файловая система временно переводится в режим записи для init hook;
после операции восстанавливается прежний режим монтирования.

После первой установки программа работает в режиме `observe`.
**На этом этапе работа Алисы ещё не меняется:** переключение выполняется
отдельной командой после настройки.

### 3. Подключите нейросеть

**Подключитесь к колонке по SSH.** Все команды до конца этого раздела
выполняются на колонке.

Настройки находятся в `/data/opt/quasar-bridge/config.json`.
При первой установке можно заменить содержимое этого файла следующим примером:

```json
{
  "listen": "127.0.0.1:8443",
  "mode": "hybrid",
  "tls_cert": "",
  "tls_key": "",
  "allowed_ips": ["127.0.0.1", "::1"],
  "llm_base_url": "https://llm.example.invalid/v1",
  "llm_model": "your-model",
  "local_progress": {
    "enabled": true
  }
}
```

Замените два значения:

- `llm_base_url` — адрес API вашей нейросети с окончанием `/v1`,
  без `/chat/completions` или `/responses`;
- `llm_model` — точное название модели, указанное вашим сервисом.

`llm.example.invalid` и `your-model` — примеры, с ними подключение не заработает.
API должен поддерживать Chat Completions или Responses и ответы в формате JSON.
Для Responses API OpenAI добавьте `"llm_api": "responses"`; для reasoning-модели
можно также задать `"llm_reasoning_effort": "low"`. По умолчанию используется
Chat Completions. [Настройки API, инструментов и лимита токенов](docs/guide.md#api-llm).

Режим `hybrid` включает выбор между Яндексом и вашей нейросетью.
Параметр `local_progress` помогает колонке дождаться долгого ответа.
Остальные параметры в примере оставляют программу доступной только внутри
самой колонки.

Если нужен ключ API, создайте файл `/data/opt/quasar-bridge/runtime.env`
и запишите в него:

```sh
QUASAR_LLM_API_KEY='ваш-ключ-api'
```

Если файл уже существует, добавьте или измените нужную строку,
сохранив остальные настройки. Ограничьте доступ к файлам:

```sh
chmod 600 /data/opt/quasar-bridge/config.json /data/opt/quasar-bridge/runtime.env
```

Если ключ не требуется и файла `runtime.env` нет, примените `chmod 600`
только к `config.json`.

Проверьте настройки, перезапустите программу и проверьте подключение к нейросети:

```sh
pkg=/data/opt/quasar-bridge/app
sh "$pkg/control.sh" check
sh "$pkg/control.sh" restart
sh "$pkg/start.sh" -check-backends
```

Без Home Assistant успешная проверка покажет
`LLM: ok; Home Assistant: disabled`. Здесь `disabled` означает, что подключение
умного дома выключено; это нормально.

### 4. Подключите Алису к Quasar Bridge

**В том же SSH-сеансе на колонке** выполните:

```sh
pkg=/data/opt/quasar-bridge/app
sh "$pkg/control.sh" apply
reboot
```

Команда `apply` сохраняет прежний адрес подключения Алисы и направляет запросы
через Quasar Bridge. Перезагружайте колонку только после успешного выполнения
этой команды. После перезагрузки проверьте два запроса:

1. «Алиса, какая завтра погода?» — должен ответить Яндекс.
2. «Алиса, спроси нейросеть: почему небо голубое?» — должна ответить ваша модель.

Если что-то не работает, начните с [проверок ниже](#если-что-то-не-работает).
Вернуться к прежней работе можно по [инструкции отката](#как-вернуть-прежнюю-работу-алисы).

## Подключение Home Assistant

Этот шаг нужен только для управления устройствами Home Assistant.
Без него команды умного дома остаются у Яндекса.

1. Установите совместимый MCP-сервер, например
   [ha-mcp](https://github.com/homeassistant-ai/ha-mcp). Подходит HTTP-подключение
   по секретной ссылке, без интерактивного входа. Обычный встроенный MCP-сервер
   Home Assistant с другим набором инструментов не подойдёт.
2. В Home Assistant разрешите нужные устройства для **Assist**. Проверьте,
   что у них понятные названия и указаны комнаты.
3. Добавьте полный адрес MCP-сервера в `runtime.env` на колонке:

   ```sh
   QUASAR_HOME_MCP_URL='https://home.example.invalid/mcp'
   ```

   Замените пример своим адресом, включая секретную часть ссылки.
4. Перезапустите Quasar Bridge и повторите проверку `-check-backends`
   из шага 3 установки.

После этого попробуйте: «Алиса, горит ли свет в кабинете?» Назовите свою комнату.
Затем проверьте включение или выключение одного устройства и посмотрите,
изменилось ли его состояние в Home Assistant.

Если Home Assistant настроен, но недоступен, программа сообщит об ошибке.
Она не отправляет ту же команду повторно в Яндекс: устройство могло уже
выполнить действие. После тайм-аута сначала проверьте его состояние.

[Подробная настройка и требования к MCP-серверу](docs/guide.md#home-assistant-mcp).

## Дополнительные возможности

В минимальном примере выше эти функции, кроме короткой памяти диалога,
ещё не включены. Их настройки добавляются в `config.json`.

| Возможность | Как пользоваться и где настроить |
| --- | --- |
| Уточняющие вопросы | По умолчанию нейросеть помнит до шести пар вопросов и ответов в течение пяти минут бездействия. «Алиса, начни новый разговор» очищает память. [Настройки](docs/guide.md#контекст-последовательных-вопросов) |
| Чтение веб-страниц | «Алиса, прочитай страницу https://example.org и перескажи». Нужны включённые инструменты (`assistant_tools`) и модель с их поддержкой. [Настройки](docs/guide.md#инструменты-локальной-llm) |
| История разговоров | «Алиса, найди в истории, что я спрашивал про свет». Нужно включить инструменты и запись разговоров (`conversation_log`). [Настройки журнала](docs/guide.md#журнал-запросов-и-ответов) |
| Звуки на колонке | «Алиса, спроси нейросеть: воспроизведи сигнал уведомления». Инструмент `play_sound` включает встроенный сигнал или аудио по HTTP/HTTPS-ссылке. [Настройки](docs/guide.md#звуки-на-колонке) |
| Музыка с сайта | «Алиса, включи музыку с сайта example.org/music». `play_music` находит аудиоссылки на странице и включает MP3 по очереди. Голосом доступны следующий/предыдущий трек, пауза, продолжение и остановка. [Настройки и ограничения](docs/guide.md#звуки-на-колонке) |
| Другие сервисы и веб-поиск | Подключаются через свои MCP-серверы. В Responses также доступен hosted-инструмент `web_search`. [Настройки API](docs/guide.md#api-llm), [примеры MCP](docs/guide.md#свои-mcp-серверы) |
| Свои правила обработки | Можно выбрать, какие фразы направлять нейросети, Home Assistant или Яндексу. [Настройки правил](docs/guide.md#правила-маршрутизации) |

Чтение страницы по ссылке и поиск в интернете — разные возможности.
Встроенный инструмент читает конкретную страницу; для поиска нужен отдельный
сервис. Страницы со входом в аккаунт или обязательным JavaScript могут
не открыться.

Тексты разговоров по умолчанию не записываются на диск. Короткая память
диалога хранится в оперативной памяти и очищается при перезапуске.
Если включить журнал, выбранные записи могут передаваться вашей нейросети
для ответа на вопросы об истории. Память одной колонки общая для всех,
кто с ней разговаривает.

## Если что-то не работает

**На колонке по SSH** посмотрите состояние и журнал службы:

```sh
sh /data/opt/quasar-bridge/app/control.sh status
sh /data/opt/quasar-bridge/app/control.sh logs
```

**На колонке по SSH** проверьте настройки и доступность сервисов:

```sh
pkg=/data/opt/quasar-bridge/app
sh "$pkg/control.sh" check
sh "$pkg/start.sh" -check-backends
wget -q -O - http://127.0.0.1:8443/healthz
```

| Проблема | Что проверить |
| --- | --- |
| Алиса отвечает как раньше, нейросеть не используется | В `config.json` должен быть `"mode": "hybrid"`. Выполнен ли `apply` и перезагружена ли колонка? |
| Проверка нейросети завершается ошибкой | Адрес API с `/v1`, название модели, ключ и доступ к API с колонки. При ошибке HTTP 400 проверьте совместимость API по [инструкции](docs/guide.md#api-llm) |
| Home Assistant показывает `disabled` | Не задан `QUASAR_HOME_MCP_URL`. Если умный дом не нужен, ничего исправлять не требуется |
| Устройство Home Assistant не находится | Разрешено ли оно для Assist, правильно ли названы устройство и комната? |
| Ответ обрывается после долгой паузы | Включён ли `local_progress.enabled` и перезапущена ли программа? [Подробнее](docs/guide.md#долгие-локальные-ответы-и-тайм-аут-колонки) |
| После перезагрузки Алиса перестала отвечать | Существует ли `/etc/init.d/S98quasar-bridge` и запускает ли его прошивка? Если быстро исправить не получается, восстановите прежнее подключение по инструкции ниже |

Адрес `/healthz` проверяет саму программу. Он не подтверждает, что нейросеть
доступна или что колонка слышит и озвучивает ответы.
После изменения адресов, ключей или модели программу нужно перезапустить.

Если нужна помощь, создайте [issue](https://github.com/skrashevich/quasar-bridge/issues)
и укажите модель колонки, версию архива, этап установки и текст ошибки.
Ключи API и секретные ссылки из `runtime.env` публиковать не нужно.

## Как вернуть прежнюю работу Алисы

**Сначала восстановите подключение, затем отключайте или удаляйте пакет.**
Иначе колонка продолжит обращаться к уже остановленной программе.

На колонке по SSH:

```sh
sh /data/opt/quasar-bridge/app/control.sh rollback
reboot
```

Убедитесь, что `rollback` завершился успешно и после перезагрузки Алиса
снова отвечает. Затем на колонке можно удалить программу и её автозапуск:

```sh
sh /data/opt/quasar-bridge/app/uninstall.sh
```

Удаление откажется работать, пока существует резервная копия endpoint:
сначала нужен успешный `rollback`. Настройки, ключи и журналы остаются
в `/data/opt/quasar-bridge`; установщик их не удаляет.

## Обновление

Скачайте новый `.tar.gz` и его контрольную сумму со
[страницы выпусков](https://github.com/skrashevich/quasar-bridge/releases/latest).
Проверьте архив, скопируйте его на колонку и повторите шаг 2 в **новом пустом
каталоге распаковки**. Установщик сам проверит конфиг, остановит старую версию,
заменит файлы и дождётся готовности новой. Настройки, ключи и сохранённый endpoint
останутся на месте; повторять `apply` и перезагружать колонку не требуется.
Предыдущая версия программы сохранится в `/data/opt/quasar-bridge/app.previous`.
Для ручного возврата установите сохранённый архив нужного выпуска тем же способом.
